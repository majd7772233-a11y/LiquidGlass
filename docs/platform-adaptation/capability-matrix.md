# Liquid Glass Platform Capability Matrix

**Research snapshot:** 2026-11-04. Treat this as a selection aid, not a fixed compatibility guarantee. Verify the exact project version, OS/device floor, backend, and render ownership before implementation.

| Family / concrete route | Backdrop access | Refraction route | Shader / custom drawing | Masks and motion | Accessibility integration | Version / hardware gate and honest default |
|---|---|---|---|---|---|---|
| Web DOM/CSS | CSS backdrop filtering can filter painted pixels behind an element within a backdrop root. It does not expose arbitrary DOM as a shader texture. | For L2, render the backdrop in an app-owned canvas/WebGL/WebGPU pipeline, then sample/displace that texture under a mask. | WebGL is a broadly deployed graphics route; WebGPU is feature-detected and secure-context-only in supporting browsers. | DOM clipping and CSS geometry for ordinary shapes; app-owned GPU geometry for connected organic contours. | Keep real buttons/links, focus, keyboard semantics, reduced motion, and labels in DOM. | backdrop-filter is Baseline 2024 but older clients may lack it; WebGPU remains Limited availability. Default L1 only when backdrop blur actually works. |
| Native Android Views / Canvas | A View shader filters the drawing input it is given; it is not automatic access to all pixels behind unrelated Views or separate surfaces. The app must own or explicitly capture the required backdrop. | Use an app-controlled RenderNode/Canvas or GPU texture source, then AGSL/custom GPU sampling and a shape-aware displacement mask. Validate SurfaceView/video/window boundaries. | RenderEffect is available from API 31; RuntimeShader/AGSL from API 33. Lower API levels need a compatible path or fallback. | Canvas paths, clip paths, RenderNode, and app-owned shader geometry; motion via ValueAnimator/Choreographer or existing animation framework. | Native View semantics, focus, touch targets, TalkBack, accessibility actions, and reduced-motion preference. | Check Gradle minSdk and device GPU/driver. API 31 blur and API 33 RuntimeShader are not universal on older devices and do not themselves grant backdrop capture. |
| Apple UIKit / SwiftUI | UIVisualEffectView applies system blur/vibrancy to content layered behind it. SwiftUI shader effects operate on the rendered view/layer they filter; do not assume an arbitrary background view tree is a shader input. | Use system materials for native blur; use an app-owned Metal render target/texture when actual backdrop displacement is required. Keep separate UIKit/AppKit-backed subviews out of assumptions about rasterized SwiftUI layers. | SwiftUI Shader exposes color, distortion, and layer effects; Metal gives explicit GPU render/compute control. | SwiftUI shapes/masks or Metal geometry; SwiftUI animation or a shared custom motion model. | Preserve native accessibility tree, VoiceOver, focus, Dynamic Type, Reduce Motion, and Increase Contrast behavior. | Use compile-time and runtime availability checks for the chosen SDK/deployment target. No single minimum OS is asserted for all Apple APIs in this matrix. |
| Windows desktop / WinUI Composition | Composition effect brushes process supplied images/surfaces on SpriteVisuals. The documented effect graph can reference existing surfaces/textures, not the output of other composition trees. | Supply an app-owned surface/texture or custom Direct3D render target; do not assume the Composition API can sample arbitrary sibling/window pixels. | Microsoft.UI.Composition effect graphs and Win2D effects for supported operations; custom Direct3D/Win2D rendering for a controlled scene. | SpriteVisual bounds, masks/clips, and Composition animations; complex organic masks may require custom rendering. | Keep XAML controls semantic; test UI Automation, keyboard focus, high contrast, text scaling, and reduced motion. | Check Windows App SDK and API package versions plus actual device GPU. Default to the native effect only for the behavior it provides; otherwise L0/L1. |
| Qt Quick / desktop or embedded | ShaderEffect paints a rectangle; the scene graph does not provide a general public "sample every pixel behind this item" property. Use an explicit texture or scene-graph render integration. | Supply a backdrop texture from the app-owned scene or insert controlled rendering through QRhi/QSGRenderNode. | Qt 6 ShaderEffect uses precompiled .qsb shaders and the Qt RHI can target OpenGL, Vulkan, Metal, or Direct3D; software scene graph does not render ShaderEffect. | QML shapes/clip and scene graph; custom render node for complex contours. | Preserve QML accessible roles/names, keyboard navigation, platform accessibility bridge, and reduced motion. | Verify Qt minor version, selected RHI backend, renderer logs, and hardware. Do not treat software backend as a shader fallback. |
| Unity 6 URP | Full Screen Pass can bind a camera color texture when Color is selected; only pixels already rendered at the selected injection point are available. UI rendered later is not automatically part of that texture. | Sample _BlitTexture or an app-owned render texture with a mask and bounded UV displacement; place pass at a deliberate injection point. | Full Screen Pass Renderer Feature and Shader Graph fullscreen/SRP Blit shader. | Renderer Feature injection points, stencil/mask or custom render targets; shader-driven SDF/metaball geometry and Unity animation. | Use Unity UI/EventSystem semantics, keyboard/controller navigation, and accessibility layer; shaders never replace control state. | Matrix example references Unity 6000.6 docs. Verify actual Unity editor, URP package, renderer asset, render graph, graphics API, and device. |
| Unreal Engine 5.x | Post Process Materials can sample scene color via PostProcessInput0 and can use user scene textures. This is scene/post-process data, not proof that a separately composed UMG layer is included. | Use post-process material with screen-space neighbor samples and a shape mask; move to a controlled custom render target if UI/scene composition needs another path. | Post Process material domain, SceneTexture, Post Process Volume blendables, and User Scene Textures. | Material masks/SDFs or mesh/UI geometry; animation through material parameters/Blueprint/native gameplay code. | Keep UMG/Slate controls semantic and accessible; expose gamepad/keyboard focus and nonvisual state. | Check exact UE minor version, renderer (deferred/forward), blendable location, platform RHI, and UI pass ordering. |
| Flutter | BackdropFilter filters previously painted content within its parent/ancestor clip. It can be expensive; shared BackdropKey can combine compatible filters. | ImageFilter.shader can be a candidate for a shader-backed backdrop operation where the current renderer supports it; test the exact Skia/Impeller backend and clipping. | FragmentProgram supports custom fragment shaders; shader-backed ImageFilter is Impeller-only per Flutter docs. | ClipRRect/ClipPath plus shader; implicit/spring animation or a shared ticker. | Semantics, Focus, keyboard actions, TalkBack/VoiceOver, MediaQuery motion settings, and text scaling. | Renderer/backend and platform views affect behavior. If shader ImageFilter is unavailable, use L1 or app-owned custom painter/texture route. |
| Constrained / no backdrop access | No reliable sample of background pixels, or capture is prohibited/too expensive. | No L2 claim. Only an app-owned copy of the background could open a refractive route; otherwise choose fallback. | Native shapes, static gradients, bounded custom drawing, or no shader at all. | Stable rounded paths and short bounded transitions; avoid expensive organic simulation. | High contrast, opaque fallback, stable focus and semantics, reduced motion. | Device/API/thermal/security budgets dominate. Default L0; use L1 only when blur is verified and affordable. |

## Interpretation notes

- **Backdrop access is not synonymous with blur.** Blur APIs can operate on painted content but may not expose the pixels needed for displacement vectors.
- **A shader is not a backdrop source.** It only samples the textures/resources bound to it.
- **Composition boundaries matter.** Camera, scene, DOM backdrop root, native View/Surface, SwiftUI layer, compositor visual, and game UI layers may be rendered in separate passes.
- **Masks are not a refraction proof.** A good mask can clip tint or highlights without distorting background geometry.
- **Accessibility is a separate layer.** Rendered pixels do not replace native control semantics, focus, or actions.
